# 개인정보 보호와 로컬 상태 설계

## 저장소와 사용자 데이터 분리

Git 저장소에는 Skill 코드, 일반화된 정책, 공개 채용사이트 메타데이터, 합성 예제와 테스트만 둔다. 이력서, 경력기술서, 연락처, 프로필, 로그인 세션, 쿠키, 실행 결과, 선호 기록은 저장소 밖에 둔다.

기본 저장 위치는 운영체제에 따라 다르며 `JOB_RESEARCH_MATCH_HOME`으로 변경할 수 있다.

- macOS: `~/Library/Application Support/job-research-match`
- Linux: `${XDG_DATA_HOME:-~/.local/share}/job-research-match`
- Windows: `%LOCALAPPDATA%\job-research-match`

## 로그인 정보

비밀번호나 쿠키를 JSON/TOML 설정에 저장하지 않는다. 사용자가 직접 로그인한 브라우저 세션이나 운영체제의 자격증명 저장소를 이용한다. Skill 설정에는 사이트별로 `browser-session`, `manual`, `public-only` 같은 비밀이 아닌 정책만 저장한다.

헤드리스 브라우저 세션 파일은 사실상 로그인 권한이므로 기본적으로 만들지 않는다. 꼭 필요한 경우 사용자 동의를 받고 Git 밖에서 소유자 전용 권한과 짧은 보존 기간을 적용해야 한다.

## 로컬 기억

Skill은 사용자의 관심·비관심 결정을 JSONL 이벤트로 저장하고, 이를 다시 계산하여 설명 가능한 선호 빈도를 만든다. 사용자는 언제든 특정 공고 기억 삭제, 전체 초기화, 현재 기억 조회를 요청할 수 있다.

## 설치·최초 사용 시 생성되는 파일

설치 또는 최초 사용 시 `local_state.py init`으로 저장소 밖의 비공개 상태를 초기화한다.

- `settings.json`: 비밀이 아닌 동작·보존 정책
- `targets.json`: 사용자가 명시적으로 허용한 스프레드시트·Drive 폴더·메일 검색 범위
- `profiles/`: 비식별 구조화 검색 프로필
- `workspace/`: 저장 전 검증하는 임시 초안
- `runs/`, `memory/`: 비식별 실행 요약과 명시적으로 허용된 피드백

저장소 안에서 실행 전용 공간이 꼭 필요한 경우에는 Git에서 무시되는
`workspace/job-collection/` 하위에만 임시 프로필·대상·실행 요약을 둔다. 이
폴더는 릴리스 매니페스트와 공개 번들에 포함하지 않으며, 원문 공고·인증
세션·연락처는 저장하지 않는다.

AI는 사용자에게 필요한 직무·기술·경력·지역·근무방식·고용형태·보상·제외조건·임계값을 물어보고, 저장 동의를 받은 경우에만 이 파일을 생성하거나 갱신한다. 실제 사용자 값은 공개 예제·테스트·참조 문서·Git 저장소에 기록하지 않는다.

## 공개 저장소 주의

파일을 현재 브랜치에서 삭제해도 기존 Git 이력의 개인정보는 사라지지 않는다.
과거 커밋에 개인정보가 있었다면 모든 브랜치·태그를 확인하고, 공개 기본
브랜치를 개인정보가 없는 새 루트로 교체한다. 공개 호스팅 서비스가 이전
커밋 객체를 해시로 계속 제공하면 일반 push만으로는 제거를 보장할 수 없으므로
호스팅 서비스의 삭제 절차를 별도로 요청한다.
